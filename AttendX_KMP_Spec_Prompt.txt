1. REST API CONTRACT SPECIFICATIONS
--------------------------------------------------------------------------------

1.1 Authentication & Session
- Endpoint: POST /auth/v1/token?grant_type=password (Supabase Auth / Next.js)
  Headers: 
    apikey: <SUPABASE_ANON_KEY>
    Content-Type: application/json
  Request:
    {
      "email": "employee@example.com",
      "password": "secure_password"
    }
  Response (200 OK):
    {
      "access_token": "eyJhbGciOi...",
      "refresh_token": "v-d8fsf...",
      "user": {
        "id": "e4f53c12-32...",
        "email": "employee@example.com"
      }
    }

1.2 User Profile
- Endpoint: GET /api/user/profile
  Headers: 
    Authorization: Bearer <access_token>
  Response (200 OK):
    {
      "id": "e4f53c12-32...",
      "name": "Employee Name",
      "email": "employee@example.com",
      "role": "EMPLOYEE",
      "department": "IT Support"
    }

1.3 Geofence Office Locations
- Endpoint: GET /api/locations
  Headers: 
    Authorization: Bearer <access_token>
  Response (200 OK):
    [
      {
        "id": "loc_colombo_01",
        "name": "Head Office - Colombo",
        "latitude": 6.9271,
        "longitude": 79.8612,
        "radius": 150.0
      }
    ]

1.4 Attendance Punch (Check-In & Check-Out)
- Endpoint: GET /api/attendance
  Headers: 
    Authorization: Bearer <access_token>
  Response: List of user attendance logs.

- Endpoint: POST /api/attendance
  Headers: 
    Authorization: Bearer <access_token>
    Content-Type: application/json
  Request:
    {
      "locationId": "loc_colombo_01",
      "latitude": 6.92714,
      "longitude": 79.86121,
      "type": "CHECK_IN" 
    }
    (Note: type can be either "CHECK_IN" or "CHECK_OUT")
  Response (200 OK):
    {
      "success": true,
      "message": "Punch recorded successfully",
      "isLate": false
    }

1.5 Gate Pass / Admin QR Punch
- Endpoint: POST /api/admin/scan-punch
  Headers: 
    x-gate-passcode: HR
    Content-Type: application/json
  Request:
    {
      "userId": "user_guid_123",
      "locationId": "loc_colombo_01"
    }
  Response (200 OK):
    {
      "success": true,
      "punchType": "CHECK_IN",
      "userName": "Employee Name"
    }

1.6 Leave Management
- Endpoint: GET /api/leave-balances
  Response:
    [
      { "type": "ANNUAL", "allocated": 14, "used": 3, "remaining": 11 },
      { "type": "CASUAL", "allocated": 7, "used": 2, "remaining": 5 },
      { "type": "MEDICAL", "allocated": 7, "used": 0, "remaining": 7 }
    ]

- Endpoint: POST /api/leave-requests
  Request:
    {
      "leaveTypeId": "leave_type_guid",
      "startDate": "2026-10-15",
      "endDate": "2026-10-16",
      "reason": "Family emergency"
    }

You are an expert Principal Mobile Software Architect specializing in Kotlin
Multiplatform (KMP) and Compose Multiplatform for Android and iOS.

Attendance & HR Employee Self-Service Mobile Application named 'AttendX'.

- UI Design: Material 3, Dark/Light mode, Smooth animations, Card components
- State Management: MVVM / MVI using ViewModel and StateFlow / SharedFlow
- Networking: Ktor Client (CIO for Android / Darwin for iOS), Kotlinx Serialization
- Storage: Multiplatform Settings (Encrypted for auth tokens) and Room/SQLDelight
- Dependency Injection: Koin Multiplatform
- Location: expect/actual pattern (Google FusedLocation on Android, CLLocation on iOS)
- Navigation: Compose Multiplatform Navigation or Voyager

ARCHITECTURE AND QUALITY STANDARDS:
- Follow strict Clean Architecture:
  1. Data layer: DTOs, API services, Repository implementations, Data sources
  2. Domain layer: Business models, Repository interfaces, Use cases
  3. Presentation layer: UI screens, Components, ViewModels, UI State, UI Events
- Keep common code in commonMain; native bridges strictly in androidMain / iosMain.
- Include proper error handling, network failure recovery, loading states, and offline queueing.
